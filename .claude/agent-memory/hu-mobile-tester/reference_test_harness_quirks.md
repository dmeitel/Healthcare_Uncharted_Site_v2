- **Eleventy `--serve` live-reload fires a FULL PAGE RELOAD every time any file lands in the project dir, and Playwright MCP writes its snapshots/console logs into `<project>/.playwright-mcp/` and screenshots into `tmp/mobile/`. That is a feedback loop: mid-test the page silently reloads and every multi-step sequence lies.** Seen 2026-08-18: 8 reloads in 17 seconds, plus one navigation to `about:blank`. Fix at the start of any dev-server session: `await page.route('**/.11ty/**', r => r.abort())` inside `browser_run_code_unsafe`. That kills the injected reload client only (dev-server code, not site code) and the page goes stable. Cost: one bogus console error, `Failed to load resource: net::ERR_FAILED @ /.11ty/reload-client.js` — filter it out of console reports. Also verify page identity with `performance.timeOrigin` before trusting a sequence.
- **Tap-target floors on this site are behind `@media (hover:none)` (hu-global.css ~line 717), so `browser_resize` / `setViewportSize` alone measures the DESKTOP sizes and produces false "under 44px" findings.** Measured `.pop-opt` at 30px and the sheet close X at 24px that way; with CDP `Emulation.setTouchEmulationEnabled{enabled:true,maxTouchPoints:5}` + `Emulation.setDeviceMetricsOverride{mobile:true}` the same elements are exactly 44px. Always flip touch emulation on (and confirm `matchMedia('(hover:none)').matches === true`) before reporting any tap-target defect. Note `Emulation.setEmulatedMedia` with hover/pointer features does NOT work for this.
- Screenshot save path MUST use lowercase drive letter: `c:/Users/david/...` — capital `C:` fails the allowed-roots check in browser_take_screenshot. Inside `browser_run_code_unsafe`, `page.screenshot({path:'tmp/mobile/x.png'})` works and is relative to the project root.
- Serve the freshly built `_site` yourself (`npx http-server _site -p 8099 -s`) when you own the server; the Eleventy dev server caches `_data`. When the parent hands you a running dev server, use it but state the staleness caveat.
- **The viewport can silently reset to a desktop size** after a long pause or session interruption. Always re-assert the size and confirm `window.innerWidth` before measuring.
- Real touch gestures: `browser_run_code_unsafe` + a CDP session (`Input.dispatchTouchEvent` with touchStart/touchMove loop/touchEnd) works well and is the only way to test scroll-vs-tap disambiguation, map pan/pinch, and sheet drags. Playwright's `.click()` does not exercise touch handlers.
- Sheet drag detents: dragging the `.hu-sheet-grab` handle steps full → half → peek and only closes on a SECOND drag from peek. One long swipe landing on peek instead of closing is by design.
- Career-tree and atlas boards are SVG canvases with `touch-action:none`; a11y snapshot `box=` coords for hex children can be pre-transform — trust elementFromPoint + getBoundingClientRect. Atlas hexes are NOT `<canvas>`: the board is `#atlas-svg > #atlas-g`, terrain rings are `#frontier-g` paths, and `elementFromPoint` over terrain returns the `url(#bg-dot)` rect, not the hex.
- Atlas board coordinates that reliably hit distinct nodes at 1280x900: (413,375) payer/drg · (450,410) payer/commercial · (520,470) payer/medicare · (600,350) medsci/evidence · (700,600) patient/pt-fin · (540,650) techeco/hie · (820,400) provider/informatics.
- Career-tree deck controls are `g.hct-cact` (rect+path, no aria-label); find them by class. Hex LABELS are canvas-rendered, so verify expand/collapse by counting `svg g` elements, not text.
- Career-tree phone flow selectors: `#hct-phone-flow`, `.hpf-deck`, `.hpf-lhd`, `.hpf-role`. Sheet = `#hct-panel.open`, real close X = `button.hct-p-close`.
- Iceberg nodes are `.nc` DIVs; selected node carries `sl`; the phone sheet is `#rp` (`rp-open`).
- Tap-target sweeps return many false positives from closed drawers/dialogs. Filter by walking ancestors for display:none AND sanity-check against a screenshot.
- Detail sheets here often stay mounted after close (hu-drawer pattern) — check visibility/class, not just presence.
- hospital-map's `.hu-sheet-grab` carries aria-label "Resize. Drag down past the bottom to close" — `[aria-label*="close" i]` hits IT before the real X. Target `button.hm-dp-close` / `button.hct-p-close` explicitly.
- Buffered PerformanceObserver layout-shift works for CLS after the fact; the "Deprecated API" warning is from the probe.
- goatcounter "not counting because of: localhost" is expected noise on every page. Both MapLibre tools also log a MapLibre `Image "circle-11" could not be loaded` warning on load.
- assignment-compass logs a 404 on `/.netlify/functions/perdiem?...` against any local server (the function only exists on Netlify). The tool degrades to an "Offline: standard rate" badge, so it is env noise, not a defect.
- When a CSS fix "landed in source" but the browser disagrees, check rule ORDER in the built file before re-measuring: same-specificity ID rules where a later base rule beats an earlier `@media` override bit the atlas find-bar twice.
- **CDP `Emulation.setDeviceMetricsOverride` LEAKS between `browser_run_code_unsafe` calls and then pins the viewport.** Seen 2026-08-22: set 390 in call A, call B measured 1274/1280 mid-sequence; later calls asking for 360 kept reporting 390, and the override RE-ASSERTED on every `page.goto`. A `clearDeviceMetricsOverride` from a *new* CDP session does not undo another session's override. Half a phone run was measured at desktop width before this was caught. **Recipe that is stable: `browser_resize` (or `page.setViewportSize`) for geometry + CDP `Emulation.setTouchEmulationEnabled{enabled:true,maxTouchPoints:5}` for the touch media features, and NOTHING else.** That combination gives `matchMedia('(hover:none)').matches === true` and `(pointer:coarse)` true, which is all the `@media (hover:none)` tap-target floors need. If the viewport is already pinned, open a new tab (`browser_tabs new`) to get a clean page. Always re-read `window.innerWidth` inside the same evaluate that measures, and discard any measurement whose width is not what you asked for.
- `page.tap()` fails with "The page does not support tap. Use hasTouch context option" — the MCP context has no hasTouch. Real taps must go through CDP `Input.dispatchTouchEvent` (touchStart with `{x,y,id,radiusX,radiusY,force}` then touchEnd with an empty touchPoints array). Chromium synthesizes the click from that correctly.
- A freshly opened tab has no `page.route` block, so the 11ty reload client connects and the console reads `[11ty] Connected` with **0 errors** — handy for a clean baseline console reading before you install the `**/.11ty/**` abort.
- **`.hu-shell` is `overflow-x: clip`, so `documentElement.scrollWidth === clientWidth` will report "no horizontal overflow" on tool pages even when controls are laid out entirely past the right edge and are unreachable.** Seen 2026-08-22 on assignment-compass: doc reported clean at 360/390/430 while `#acMethodBtn` sat at left:389 with `elementFromPoint` = NULL. **Never conclude "no overflow" from the document metric alone on a `.hu-shell` page.** Walk elements and compare each `getBoundingClientRect().right` to `documentElement.clientWidth`, then confirm reachability with `elementFromPoint` at the element's center. `clip` (unlike `auto`) gives no scrollbar and no recovery, so anything past the edge is simply gone.
- Chromium desktop keeps a 6px classic scrollbar, so at a 390 viewport `clientWidth` is 384. Report tap/clip geometry against `clientWidth`, and remember a real phone's overlay scrollbar gives back those 6px (it will not rescue anything overflowing by more than that).
- `env(safe-area-inset-*)` computes to 0 in this harness, so a correct `calc(8px + env(safe-area-inset-bottom))` reads as plain `8px` in `getComputedStyle`. Check the CSS source before calling a fixed bottom bar unsafe.
- Verifying an inline-script → ES module extraction is fastest from git, not the browser: `git show HEAD:<page> | awk '/^<script>$/{f=1;next} /^<\/script>$/{f=0} f' > /tmp/old.js` then `diff` against the new module. Both extractions so far (vendor-directory run 5, assignment-compass run 6) were faithful moves, so the diff is small and the remaining browser time belongs on the risky seams the parent names.
- **Proving a WebGL map actually repainted: screenshot a fixed clip of the map and hash the PNG bytes** (`page.screenshot({clip,scale:'css'})` then a rolling hash in the same `browser_run_code_unsafe` call). MapLibre runs `preserveDrawingBuffer:false` so `canvas.toDataURL` is blank, and the map instance is inside an IIFE so there is no global handle for `queryRenderedFeatures`. Distinct hashes across metric/year switches is the only cheap proof that "the data arrived". `require` is NOT available inside `browser_run_code_unsafe`, so no `crypto` — write the hash loop by hand.
- **Parsing a `<script type="application/json">` block out of served HTML with a JS regex silently fails on big blocks.** Use `indexOf(open)` + `indexOf('<'+'/script>')` and slice. (Splitting the closing tag literal also keeps the extractor script from terminating itself.)
- **When a URL param goes missing on phone but not desktop, shim `history`**: wrap `pushState`/`replaceState` to log `{method, url, stack.slice(2,5)}` and add a `popstate` listener that logs `location.search`. That is what caught the multi-lens-map backGuard eating a correct `replaceState` 10ms later. Read the stack frames: they name the kit function (`arm`, `Object.sync`) and the tool function (`syncURL`, `metricChanged`).
- `HUKit.phone()` is `matchMedia('(max-width:699px)')`, WIDTH ONLY. At 844x390 landscape it is FALSE, so phone fit padding, `dcap()` animation clamping, and `backGuard` all silently switch to desktop behaviour on a phone held sideways. Always check `phone()` explicitly when testing landscape on a tool page.

- **MapLibre names the fitBounds-padding failure out loud: `Map cannot fit within canvas with the given bounds, padding, and/or offset.`** That warning is the definitive proof that `fitPad().top + .bottom` exceeds the map container height, and the camera then does NOT move at all. Always capture console WARNINGS (not just errors) when testing any fit/zoom behaviour, and bisect with a taller viewport to find the threshold (e.g. warning at 844x390 but gone at 844x430 pins the shell height that works).
- An absolutely positioned bar with `left:50%; transform:translateX(-50%)` and NO `right` has a shrink-to-fit available width of only `containing block − 50%` (180px at 360, 195 at 390, 215 at 430). The transform does not give the width back. Any flex child without `flex:none` gets squeezed and its text wraps/clips. That is how operators-map's `#gvListBtn` count broke.
- Both maps' catalog/metric option rows (`.pop-opt`) pack sub-controls ("◯ Size", "☆ Pin") into the LOWER half of the row. A tap at the row's vertical midpoint hits the overlay control and writes `?ov=…`, not `?metric=…`. Aim at the title line (`el.querySelector('div')` bounding box) to pick the metric.
- operators-map selectors: sheet grab = `button.hu-sheet-grab` (352x20, `[class*=grab]` matches the SHEET first because it carries `has-grab`); desktop drawer grip = `div.gv-resize` (not `[class*=grip]`); Display panel opens via `#gvLayersPill` / `#gvTypesPill` / `#gvDisplayPill`, but `#gvDisplayPill` goes invisible once a state is selected — use `#gvTabs button[data-tab="display"]` then.
- `#gvSheetX` on operators-map is a BACK-WALK, not a close: from the state card it calls `deselectState()` and returns to the US view. To dismiss the sheet without losing scope, drag `button.hu-sheet-grab` down twice.
- `CDP Emulation.setTouchEmulationEnabled` rejects `maxTouchPoints:0` ("Touch points must be between 1 and 16"). To turn touch OFF pass `{enabled:false}` alone, or just open a fresh tab.
- `page.addInitScript` survives subsequent `page.goto` calls in the same MCP session, so a `history` shim installed once keeps logging across reloads and navigations. Handy, but remember to clear `window.__H` between steps or the trace concatenates.
- **To read a MapLibre map's real camera when the instance is trapped in an IIFE, hook the constructor from `addInitScript` with a `window.maplibregl` property setter** (maplibre-gl.js is UMD and assigns the global, so the setter fires before the deferred tool module constructs anything): wrap `v.Map` so every instance lands in `window.__maps`, then read `getZoom()` / `getCenter()`. This is the ONLY reliable proof of whether a fit/zoom actually happened. Pixel hashes lie (polygons and chrome repaint anyway) and an in-view facility count lies too (it conflates zoom with center: Texas shows FEWER facilities when zoomed out because its frame covers the empty Gulf).
- **The absence of MapLibre's `Map cannot fit within canvas` warning does NOT mean a fit succeeded.** A padding clamp can silence the warning while still producing a fit box so short that `fitBounds` (which takes the min of the width-fit and height-fit zooms) zooms the camera OUT. Always compare `getZoom()` before and after.
- **Career tree lives at `/tools/career-tree/`, NOT `/tools/healthcare-career-tree/`** (the older auto-memory index is stale). All eight tool URLs verified 200 on 2026-08-22: `/tools/{vendor-directory,multi-lens-map,operators-map,iceberg-map,hospital-map,career-tree,sql-mystery}/` and `/atlas/`.
- **Fastest discoverability harness: two `page.evaluate` passes and a set-difference.** Pass A at 390 collects every interactive element intersecting `[0, innerHeight)` with rect, computed font-size, aria-label, title, and a truncation probe. Pass B keys every interactive element by `#id` or `tag.firstClass` and counts visible-vs-total, run once at 390 and once at 1280 (`page.setViewportSize` only — never CDP device metrics); anything visible at 1280 and not at 390 is a hidden-on-phone control. Cost is ~1 call per tool.
- **To quote what a truncated label ACTUALLY shows**, don't guess from the ellipsis: clone the computed `font` onto an offscreen probe span and grow the string one char at a time until `offsetWidth > el.clientWidth`. That produced "Patient · Life ex…" and "Search 5,366 …" exactly.
- **`elementFromPoint` at an element's own center is the only honest reachability test on a phone.** hospital-map's legend chips report a normal 44px box and a real class while sitting outside their `overflow:auto` parent's paint box; `hit` came back as `SPAN.tool-bar-kicker` / `DIV.hm-subbar` / `OFFSCREEN`, never `self`.
- **A flex rail with `justify-content:flex-end` + `overflow-x:auto` cannot scroll to its own overflow.** Prove it by assigning `scrollLeft = -9999` and `= 9999` and reading both back: hospital-map returns 0 and 2 against content spanning −225..378.
- Atlas hex coordinates that hit the PAYER cluster at **390x844**: (110, 445) selects Payer & Payment › Coding & CDI (it selected Utilization Management in run 9, so the mapping DRIFTS between runs — always read `location.hash` back, never assume). Others verified run 10: (150,470) `#payer/vbc`, (190,430) `#medsci/nlp`, (130,520) `#payer/medicare-adv`. The 1280x900 coordinate list elsewhere in this file does not transfer.
- **Before measuring any "we set it to 44px" fix, assert the selector matches something: `document.querySelectorAll(sel).length`.** Run 10 lost time on iceberg's `button.hi{min-width:44px}` where the element is `<div class="hi" role="button">`, so the count is 0 and the control silently stayed 32x32. Same family as the rule-order trap, different cause. Check tag name, not just class.
- **Reachability on an `overflow-x:auto` rail must be probed at INTERMEDIATE scroll positions, not just 0 and max.** A chip can straddle the clip edge at both extremes and still be perfectly reachable in between. Sweep `scrollLeft` in ~20px steps and record the first position where `elementFromPoint` returns self. Testing only the two endpoints reported hospital-map's "Support" chip as unreachable at 360 when all 8 are in fact reachable.
- **When a fix stops one flex child from being crushed, re-measure the WHOLE bar.** In a `flex-wrap:nowrap` bar the crushed child was absorbing the overflow; giving it its natural width shoves the same pixels onto the siblings, and if an ancestor is `overflow:hidden` they vanish with no scrollbar. Iceberg run 10: `#bc` went 3.2 → 89.4px and `#selViews` + `.hics` went off-screen; `#tb` scrollWidth 454 vs clientWidth 384. **The control experiment is cheap and decisive: set the property back in the live page (`bc.style.flex='1'`), force layout, re-measure the siblings, then restore.**
- hospital-map pinch/pan transform target is **`.hm-campus-col`**, not `.hm-building-scroll.children[0]` (that is the 0x0 `#hmPzReset`). Read scale with `new DOMMatrix(getComputedStyle(el).transform).a`. Landing scale is 0.3.
- Layout-shift attribution: add `sources` to the PerformanceObserver handler and read `s.node` + `previousRect`/`currentRect`. That is what pinned vendor-directory's CLS to `div.vd-board` collapsing to [0,0,0,0] at t=139ms. Note CLS varies run to run (0.2155 vs 0.3237 on identical loads) — report the range, not a single figure.
- `scrollIntoView()` can silently under-scroll on very tall pages (vendor-directory, docH 44,769): it left the target 13,323px below the fold. Use `window.scrollTo(0, rect.top + scrollY - offset)` and verify `scrollY` afterwards.
- **A fixed `height` on a wrapped flex bar is a breakpoint bomb: it fits at the width you tested and spills at the next one down.** Iceberg run 10b: `#tb{flex-wrap:wrap;height:88px}` fits 2 rows at 390/430 but needs 3 rows (118px) at 360, and `align-content:center` then pushes content OUT BOTH ENDS of the box, over the content below. **Always measure the bar's natural height by setting `height:'auto'` in the live page and reading it back**, then compare to the declared height at every width.
- **Before trusting a paired-number layout (`#bar{height:N}` + `#content{top:N}`), check whether the positioned property is even live.** On iceberg phone both `#tb` and `#ct` are `position:static`, so `#ct{top:88px}` is dead code and the seam is held by normal flow. `getComputedStyle(el).top` returning a value does NOT mean it is used — check `position` first, and derive the real offset as `rect.top - offsetParent.rect.top`.
- To prove a sticky seam does not leak, **probe every pixel row between the two bars with `elementFromPoint`**, not just the midpoint, and classify each hit as in-bar vs page content. That is how the vendor 4px `div.vc-desc` slot was found and then confirmed closed.
- Iceberg layer popover options carry `data-focus` (all/Experience/Operational/Financial) and `data-layer` (1-8). Pick them by dataset, not by text regex, and skip index 0 which is the `icon-btn` close X. `data-focus` updates the `#selLayer` face and writes `?focus=`; `data-layer` toggles visibility and writes `?hide=`.
- **`page.addInitScript` ACCUMULATES across `browser_run_code_unsafe` calls on the same page, and every copy runs.** N accumulated copies means N PerformanceObservers all doing `window.__v.cls += e.value` against the same object, so **CLS and long-task counts come back multiplied by N**. Seen 2026-08-22 (perf run): career-tree read CLS 1.6971 desktop / 1.1418 phone; the true values on a clean page are 0.0019 / 0.1915. Two defences, use both: guard the init script with `if (window.__vInstalled) return;`, and **measure vitals on a fresh `page.context().newPage()` per navigation** (close it after). Network/CDP byte capture is NOT affected — the CDP session and its `reqs` map are per-call.
- `browser_run_code_unsafe` runs in a restricted Node scope: **`URL` is not defined** (and `require` isn't either). Use `u.indexOf(origin) === 0` and a regex for origin parsing instead of `new URL()`.
- Code files for the `filename:` parameter must live under an allowed root — `c:\Users\david\Documents\Healthcare_Uncharted_Site` or its `.playwright-mcp\`. The session scratchpad under AppData is REJECTED ("outside allowed roots"). Write the template to the scratchpad, then copy generated per-page variants into `.playwright-mcp/perf/`.
- **True transferred bytes incl. cross-origin: CDP `Network.enable` + `Network.setCacheDisabled{true}`, then tally `Network.loadingFinished.encodedDataLength`.** `performance.getEntriesByType('resource')` under-reports cross-origin without Timing-Allow-Origin. Pair `requestWillBeSent.timestamp` with the first request's timestamp for a "fetched at +Nms" column, which is what proves a dataset is boot-time vs on-demand.
- **CSS coverage: CDP `CSS.startRuleUsageTracking` → `CSS.stopRuleUsageTracking`.** It only reports rules that MATCHED, so `used === total` in every row; compute coverage as `used / styleSheetText.length` via `CSS.getStyleSheetText`. Caveat worth stating in any report: interaction-only rules (open sheets, :hover, .active) read as unused, so this is a ceiling on savings, not deletable bytes.
- **To prove a font file is downloaded but renders nothing, use CDP `CSS.getPlatformFontsForNode` over every node and tally `glyphCount` by family.** Scanning `getComputedStyle(el).fontStyle === 'italic'` misses pseudo-elements and lies; the platform-font tally is definitive. That is how DM Sans italic (28.5 KB, fetched on 8 of 9 pages) was shown to render 0 glyphs on `/`, `/tools/`, `/atlas/`.
- **Size a "defer this dataset" win with a block-and-compare A/B in one call**: `page.route('**/file.json', r => r.abort())` on a fresh page, then diff total bytes / TBT / FCP against baseline. Cheap and it kills speculation — it showed blocking d3 on the atlas did NOT improve FCP (the 153ms long task is the page's own 180 KB inline script building 5,053 nodes), so "defer d3" would have been a fake fix.
- Local dev serves UNCOMPRESSED and has no CDN. Always report raw bytes, and pull `gzip -9 -c file | wc -c` alongside for the production-shaped number — the ratios vary enormously (search-graph.json 11.56 MB → 1.08 MB, but countyData.json 724 KB → only 217 KB).

- **MapLibre's `e.point` and `map.queryRenderedFeatures([x,y])` are CANVAS-relative, and on both map tools the canvas starts at y=64 on phone** (`#lvMap` / `#gvMap` `getBoundingClientRect().y`). A CDP `Input.dispatchTouchEvent` takes VIEWPORT coordinates. Mixing them silently taps ~64px north of the intended feature: run 12 read "Moffat, CO" from the query and selected Wyoming, then spent three calls chasing a phantom. **Always read the map element's `rect.y` once and add it when converting a queried point into a tap.** States are big enough to survive the error; counties and pins are not.
- **`globalThis` (and `global`, which is simply undefined) do NOT persist between `browser_run_code_unsafe` calls.** `global` throws `ReferenceError: global is not defined`; a value written to `globalThis` in call A reads back as undefined in call B. Any multi-step sequence that needs the same `page` handle plus its CDP listeners must live inside ONE call.
- **To tell "renders empty then repairs" apart from "renders empty forever" on a deferred fetch, throttle AFTER load with CDP `Network.emulateNetworkConditions` ({latency:150, downloadThroughput:1.6*1024*1024/8}) and snapshot the card at 0/300/700/1500/3000/5000/8000 ms.** On localhost a 724 KB file lands in <150 ms, so both behaviours look identical and a genuine multi-second hole reads as a pass. That is how operators-map's 5-second missing Population/Beds/shade-button window was measured and, by contrast, multi-lens' permanent `—` was proved permanent.
- `#lvScope` (multi-lens) and `#gvScope` (operators) carry the `hidden` attribute at the US view, so `page.click` blocks for the full 30s timeout waiting for visibility. Check `el.hidden` first, or drive them with `p.evaluate(() => el.click())`.
- Before blaming a deferral for a missing card field, `git show HEAD:<file> | grep` the producer. Run 12's "facility card lost its county context" was operators' `toFeatures()` never copying `co` in the first place — dead at HEAD, unrelated to the change under test.
- **`setTimeout` is NOT defined in the `browser_run_code_unsafe` Node scope either** (same restricted scope that lacks `require`, `URL`, `global`, and persistent `globalThis`). So a `page.route(url, async r => { await new Promise(z => setTimeout(z, 4000)); r.continue(); })` delay-injector throws. To slow ONE big response instead, apply CDP `Network.emulateNetworkConditions` with a throughput chosen from the file size (`downloadThroughput: 2.5*1024*1024` makes the 11.56 MB atlas graph take ~4.6 s) AFTER the page has loaded, so page load itself stays fast. Reset with `{latency:0, downloadThroughput:-1, uploadThroughput:-1}`.
- **To verify a "renders placeholder, then repairs" fix, install a MutationObserver via `addInitScript` that pushes `{ms, <the field you care about>}` on every mutation, and read the array at the end.** Polling with `waitForTimeout` snapshots misses the transition entirely when the gap is tens of ms on localhost: multi-lens' repaired Population went `——`@6545ms → `6.0M`@6581ms, a 36 ms window no sampling schedule would have caught. The observer array also proves the card rendered exactly TWICE, which is how you know the fix did not introduce a re-render loop. Guard it with `if (window.__obs) return;` and reset `window.__c0` right before the interaction so the timestamps are action-relative.
- Pair every localhost pass of a deferred-data fix with a throttled repeat and report BOTH numbers. Localhost said multi-lens' dash flash was 36 ms; at 1.6 Mbps/150 ms the same flash is **6.9 seconds**. Only the second number tells you whether the placeholder still needs a label.

- **A page download (anchor-click JPG export etc.) ABORTS the in-flight `browser_run_code_unsafe` call with a bare `Error: canceled` — but the download itself completes and the page is fine.** Seen 3x on /learn/request-routing/'s `#rrFlowDl`. Recipe: put the download-triggering click LAST in its own call, then read the proof (`dataset.bytes`, button text cycle) in the NEXT call. Do not report the abort as a page error.
- **This site sets `html{scroll-behavior:smooth}`, so EVERY programmatic `scrollTo`/`scrollIntoView` animates.** Reads and `elementFromPoint` right after a scroll race the animation (produced a false NULL reachability and misplaced screenshots). Always pass `behavior:'instant'`, or wait ~900ms. A screenshot mid smooth-scroll can even show stale compositor content — never diagnose layout from one.
- **hu-global.css:84 styles the bare `nav` ELEMENT: `position:sticky; top:0; z-index:200; height:64px` + translucent bg.** Every in-page `<nav>` inherits it. 4ps `.section-nav` and laws `.lp-tabs` override to sticky top:64px with a low z; any NEW page with a nested nav that doesn't override will cover the site nav on scroll-up. Check this first on any new Learn/section page with tabs in a `<nav>`.
- **SVG clip checks via `getBBox()` false-positive on transformed text**: bbox is pre-transform local units, so a `rotate(90 x y)` caption near the right edge reads as past the viewBox while rendering fine. Check the `transform` attribute before reporting, then confirm with a screenshot.
- In this harness (viewport resize + touch emulation, NO mobile device metrics), `overflow-x:auto` rails draw a CLASSIC ~14px horizontal scrollbar inside their box — the gray strip under request-routing's tab rail is that, not a page element. Real phones get overlay thumbs.
