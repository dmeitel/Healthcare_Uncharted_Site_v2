Site-wide audit 2026-08-22 (read-only). Six defect classes recur (seven more added 2026-09-23), and most trace to a SHARED file, so one diff there beats eight page diffs.

**Why:** a defect in `hu-global.css`, `base.njk`, `hu-kit.js`, `rounds.css` or `components/tool-attribution.njk` multiplies across every page that loads it. Ranking by origin file, not by page count, is how the fix budget stays small.

**How to apply:** when a new finding lands, check whether it belongs to one of these classes first; if so, fix at the origin and re-check the consumers rather than patching the page in front of you.

1. **Teal-as-text with no light-theme override.** Origin `src/assets/css/hu-global.css`. The `[data-theme="light"]` override list (lines ~48-51 plus scattered per-component rules) covers some consumers and misses others. Missed shared chrome as of this audit: `.eyebrow` / `.section-eyebrow-v2`, `.tool-bar-title span` (the tool h1 accent), `.tool-attribution .ta-brand span` + `a:hover` + `--fixed .ta-toggle:hover`, `.nav-theme-btn:hover`, `.hu-fab:hover/.is-on`, `.btn-ghost:hover`, `.btn-secondary`, and the base `a { color:var(--brand-primary) }`. Brand teal is 1.72:1 on the light page bg. See [[teal-ink-migration]] for the ruled classification method.
2. **Div/span with an onclick and no role+tabindex+key handler.** Per-page, not shared, but it clusters in the hand-coded tools: iceberg-map, sql-mystery, learn/talks/arma-2026. Semantic `<button>` is the fix, not ARIA.
3. **Focusable control with no key handler.** Origin `src/assets/js/hu-kit.js` `sheet()` — the injected `.hu-sheet-grab` button is pointer-only, so every tool that adopts the kit sheet ships one named, tabbable no-op. Same shape appears in JS-built `role="switch"` spans when the delegated Enter/Space listener is bound to the wrong container.
4. **Custom tabs that never announce state.** Origin: per-page. `src/index.html` has the CORRECT reference implementation (role tablist/tab/tabpanel + aria-controls + aria-selected updated + arrow keys). Copy that one. laws-and-paradoxes and multi-lens-map both diverge from it in different directions.
5. **Focus indicator removed or absent.** Origin `hu-global.css` (`.fs-input:focus { outline:none }` in the footer form, which is on every page) and `src/assets/css/rounds.css` (zero focus rules for all four Rounds posts).
6. **Redundant `aria-label` overriding real content.** Buttons/inputs that already have a `<label for>` or visible text get an `aria-label` on top, which replaces the visible name and breaks 2.5.3. Shows up in assignment-compass, the `.hv-search` / `.lv-inset` buttons, and laws' `.jp-loop-play`.
7. **`filter:brightness()` as a contrast "fix".** Found 2026-09-23 on vendor-directory (.vc-tag/.vc-status), iceberg (.ln) and hospital-map (.hm-dp-cat-badge, replaced the same day; its JS now passes the hue as --unit-color). A filter never changes the computed color, so every audit tool still reads the raw hue, and it darkens the tint and border too. Real fix is per-hue light inks; for inline JS hues, `color-mix(in srgb, var(--hue) 50%, #000) !important` in light (clears 4.6:1 for all 8 iceberg layer hues and all hospital-map unit hues), and the same hue 50% toward #fff in dark. Sweep for `filter:brightness` in light rules elsewhere. career-tree: `.hct-zonelbl` and `.atlas-zone-lbl` moved to color-mix via a `--zc` style set in JS (2026-09-23); `.hct-phead-txt/.hct-fhead/.hct-boxlbl/.hct-doortag/.hct-benchtag` and `#hct-tip .tip-fam` still use the filter.
8. **`.hu-read-p a` outside a `.hu-read` wrapper.** Origin `hu-global.css` ~line 1661: the light link flip is scoped to `.hu-read a`, so a `.hu-read-p` paragraph in a jp `<article>` gets base teal (1.7:1). 12 learn pages use `.hu-read-p`; process-engineering got a page patch 2026-09-23. Origin fix = add `.hu-read-p a` to both 1661-1662 selectors.
9. **jp-article amber-as-text has no `--jp-amber-text` step.** Same shape as the ruled `--jp-accent-text`: `.jp-counter-label` (11px) + `.jp-counter-body a` in every jp page, plus SVG text fills (`.gh-lbl.r`, `.lpv-t.amber`, `.gx-t.amber`, `.bn-t.amber`) and `.ds-chip.amber`, all raw amber in light. Template-level fix across the 8 jp pages mirrors the 2026-08-17 ruling; not yet done.
10. **Scanner-blind contrast.** UPDATE 2026-09-23 ~01:00: scan.js was upgraded to composite bg layers, text alpha, opacity and color(srgb), and to skip :disabled; it still ignores CSS `filter`, hover, and averages gradient stops (a label centred on a .15 to .5 wash really sits on .46 to .5 at its edge). Before that upgrade: The shared whole-site scanner (tmp/theme-scan/scan.js) reads text rgb IGNORING its alpha, ignores element opacity above .3, skips any background with alpha under .6 (walks to the next opaque ground, and calls a .85 ground opaque), and SKIPS every `color(srgb ...)` value, which is how Chrome serializes any color-mix. So these pass the gate and still fail: rgba() muted text (`--mist-fade`/`--mist-soft` on home-respiratory-timeline, 2.2-3.3 both themes), opacity-faded text (oxygen .rate-context-* at .5-.8), accent text on its own 8-12% tint (pills, chips, `.dt-t`, `.jp-tldr-num` at 4.4-4.5), and the alpha-dimmed blueprint labels on hospital-map (floor labels, elevator numbers, foundation/roof labels, marquee meta/cta, SYS badges, dp section labels) and iceberg (legend .lg-grp/.lgt-s/.lg-hint, .lsu, .rh, .ts, .tsub). On 2026-09-23 it reported hospital-map 38/12 while composited truth was ~134 dark / ~82 light elements. Composite fg and the bg stack yourself before calling a fix done; a hover wash counts too. UPDATE later 2026-09-23: the lead upgraded scan.js to composite alpha, opacity and color(srgb); it still skips SVG text, cannot see position:fixed backdrops, and ignores text-shadow, so pixels remain the final word on those. The two blueprint maps' dim labels were then raised on the coordinator's GO (each alpha to its own 4.5 minimum, order of quietness kept).
11. **Kit pills under a page link rule.** Origin hu-global.css ~1677-1678: `.hu-read a:not(.toggle-chip):not(.tb-brand):not(.hu-read-link)` is (0,4,1) and repaints EVERY `.fp` chip inside a `.hu-read` wrapper teal (dark) / teal-ink (light), in both themes, on 7 learn pages (ai-in-healthcare, change-healthcare, ehr-architecture, healthcare-gap, hitech, leading, the-payer). Only fp-policy on violet fails contrast (4.43), but every chip loses its lens hue. Fix = add `:not(.fp)` to both selectors; a page-level patch would have to restate every .fp ink. Measured with a clone-outside-.hu-read comparison.

Deeper teal for TEXT on a teal wash (where teal-ink lands 4.4-4.5): `#0B6158` is the value in use (learn/sources .ai-use, home-respiratory-timeline --teal-light, jp-tldr-num on pe/ds/laws). Reuse it rather than minting another step.
12. **Text over a fixed decorative backdrop.** hospital-map `.hm-backdrop` is a position:fixed, pointer-events:none landscape (sky, hills) behind translucent building surfaces. Ancestor walks and elementsFromPoint cannot see it, so even correct DOM compositing is wrong there; only rendered pixels tell (hide the glyphs, screenshot the box, composite the computed ink over the sampled ground). In LIGHT theme the four building signs (.hm-pub-sign, .hm-bldg-sign*), the floor-label column and the marquee cta sit directly on painted hills and sky (1.0-2.7:1, varies with scroll). No ink passes on both sky and hill. MEASURED 2026-09-23: iceberg's light halo (0 1px 3px .95 + 0 0 6px .75 white) does NOT give 11px text a ground there; a blurred shadow under a thin stroke covers maybe 40%, so the glyph still sits on blue sky or dark hill (p05 1.0-2.0 with the page inks, and even #001117 only reaches 3.1 on the hills). Raising the EXISTING sign fills to the roof's rgba(220,235,255,.97) did clear the building signs and marquee in an injected test. RESOLVED same day on the coordinator's ruling: the halo came out; in light the signs and marquee take the roof's fill rgba(220,235,255,.97), the floor numbers (JS now wraps each in a span) and the "click to explore" line get small plates of that same fill (radius 3px, the marquee badge's), inks raised to --blue / .82 slate. Pixel p05 >= 4.5 at 12 scroll positions, 1280 and 390; dark pixel-identical. Dark was solved by alpha alone (floor labels need solid teal). Lesson: a halo is not a ground for 11px text on a saturated picture; reuse an existing opaque fill.
13. **Decorative HUD text raised to contrast becomes a collision.** iceberg `.hlbl` captions overlap the toolbar buttons and a layer label; raising them to 4.5 made them compete with live controls. They duplicate the h1 and subtitle, so the fix was aria-hidden (decoration, exempt), not ink. Screenshot any absolutely positioned label before brightening it.

14. **Dark-tuned shadow kept in light theme.** A floating bar with `box-shadow: ... rgba(0,0,0,.45)` and no light override greys the panel under it to #bec0bf, so headers there read 2.8:1 even at a sane ink. Atlas `#find-bar` (fixed 2026-09-23 to .14, matching the page's own `#atlas-hud` light rule). This is a GROUND defect: raising the ink alone would have needed alpha .93.
15. **Floating panel docked at a fixed `top` over in-flow chrome of variable height.** Atlas `#atlas-find` (phone `top:58px`) covers the whole breadcrumb row (and half the applied strip) at every phone size incl. 740x360, since the merged band's `.tb-brand` took toolbar row 1 and pushed the breadcrumb to row 2. Touch cannot reach Overview/zone crumbs, keyboard focus on them is fully hidden (2.4.11). `npm run phone` reports CLEAN: the gate does not test occlusion. Flagged 2026-09-23, not fixed (layout call: one-row toolbar fixes the crumbs but then buries the strip, which wraps to 80px with 4 chips; the robust fix moves #atlas-find into #atlas-canvas plus a landscape results cap).
16. **Hue passed inline as `style="color:..."` from JS** cannot take a light ink. Pass it as a custom property instead (atlas `#bc-z` --zc, `.fd-type` --tc + data-t) and let CSS do `color-mix(... 50%, #000)` in light. Same for inline `opacity` in JS templates: move it to a class so each theme gets its own value.
17. **CSS generated glyphs enter the accessible name** (`.conn-row::before` markers, read before every row). Fix: `content:'\25B8'; content:'\25B8' / '';` (the plain line is the fallback). Text separators built in JS (`›` crumbs) get aria-hidden, which also makes their faint ink exempt.

METHOD (2026-09-23, atlas): for UI floating over a scene, measure against PIXELS, not ancestors: inject `*{color:transparent!important;...}`, screenshot the ground, then composite each element's computed ink (alpha x ancestor opacity) over the p10/p50/p90 pixels under its own text Range rects. Catches scene bleed, tints, hover washes and shadows. Script lived at tmp/theme-atlas/probe.js (tmp is gitignored; may be gone). Drive interaction states, not just load: most failures on the atlas were in panels hidden at load, and two (dark Policy badge 3.9, dark Metric pill 2.75) only showed when every hue was swept analytically.

Put such a selector first in a comma list, not last, or the ratchet fails for a non-shell rule.
