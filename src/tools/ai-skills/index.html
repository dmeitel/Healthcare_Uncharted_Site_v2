Every AI tool you touch at work forgets everything between sessions. You explain your documentation format on Monday, and by Wednesday it's a stranger again. Skills fix that.

A skill is a folder with one markdown file in it, always named SKILL.md. The file holds instructions, and agents like Claude Code, Cursor, and Codex load it on their own when a task matches. Think of it as a protocol binder for the agent. You don't re-teach the ventilator weaning criteria to every therapist on every shift; the protocol is written once and everyone works from it. A skill is the same move, and it lives in git like any other artifact, so it has a history and an owner.

The developer world moved on this fast. One directory alone indexes more than nine thousand skills, and GitHub search turns up far more than that. Almost all of it is noise, and nearly none of it is written for people who work in a health system. So here's the map.

Read this before you install anything

Skills can execute code in your agent's environment. A community skill is a supply chain, and you are the last link in it.

Fine for your home lab. NOT fine for a workstation inside a health system unless you or your security team have read every line first. If you wouldn't run a random script from a forum on a machine that touches PHI, don't install a random skill on one either. Write your own where you can, and audit what you borrow line by line. The hobby laptop and the work laptop are different machines for a reason.
